# Automatic recovery evaluation protocol

Frozen before new live execution on September 21, 2026. Results belong in a separate report.

## Questions

Can DUKE detect an injected concrete failure and dispatch a bounded same-model effort retry? On fresh development tasks, how do automatic routing and recovery compare with fixed Astra Medium in independently acceptable results and model-specific cost?

## Frozen conditions

- Routing v11, review v5, recovery v1. The tested clean Git commit is recorded in every receipt.
- Default recovery ceiling Medium, at most two retries. Same-model one-rung quality repairs only. Fixed baseline effort stays fixed.
- Identical enabled roster: Codex Luna, Sol and Astra. Jev selects model and effort in the automatic condition. Baseline fixes Astra Medium. Both retain Jev review, the same tools, skills, briefs, rubrics and API limits.
- Four previously unused development cases: `coding-chunks`, `research-playwright-context`, `documents-checklist-pdf`, `writing-release`. They cover an explicit coding contract with a protected test, a supplied primary-source starting point, a complete invented document brief, and release notes constrained to supplied facts. These are fresh task variants, not a novel-domain or held-out evaluation.
- Run the automatic condition and then Astra Medium in isolated state/workspaces. No manual repairs or prompt changes after seeing results. Preserve failures and incomplete checks.
- Independent acceptance uses the frozen rubrics and actual artifacts, source checks, code assertions and rendered PDF. The reviewer is separate from the workers and Jev but knows the conditions. Offline review labor/model use is excluded equally from the execution comparison.
- Report every initial attempt, retry, routing/diagnosis/review call, API reservation, and model-specific worker usage. Use the frozen September 20 price scenario from the earlier pilot for comparability; it is not a current price quote. Subscription API equivalents are not bills or exact allowance consumption. Account snapshots remain separate observations.
- Keep the existing shared $1 API cap and lock. Reserve $0.02 for each phase and enforce a $0.02 per-phase app API limit. No paid OpenRouter worker. No external writes; unexpected approvals are denied.

## Controlled recovery probe

Run separately from the natural task comparison. Inject Luna Low as the first route and a deliberately incorrect empty-array implementation for `coding-chunks`; the first worker is synthetic and has no inference cost. The real verifier must detect its failed test. Jev must diagnose the failure live; a real Codex worker performs any approved repair. Record the injection explicitly and exclude this case from natural success and savings totals.

Success requires same-model Medium dispatch, preserved original tests, a passing independent check, complete attempt accounting, and no manual intervention after starting. A pause is retained as an outcome, not bypassed with a new prompt or a higher ceiling.

## Interpretation

Four tasks cannot establish general savings or calibrated routing quality. Distinguish first-pass success, automatic recovery, independent acceptance and Jev's review status. If no natural task fails, this cohort does not measure natural recovery success. A missed error counts as an independent failure even if Jev approves it. Held-out cases remain untouched.
